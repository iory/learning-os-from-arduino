# 07_led_matrix_v2 — LED マトリクスを「小さな top」にする

第7章 `07_led_matrix` の改良版。**書籍には載っていない**（本文と掲載コードは
`07_led_matrix` のまま）。カーネル（`os_kernel.cpp`）とフォルト処理は同じで、
変えたのは表示・シェル・タスクの中身だけ。

## 何が変わるか

マトリクスを、htop の CPU メーターのような「いまの値の横棒」にした。どの棒も
**12 個で 100%**、0.5 秒ごとに測り直す。

| 行 | 中身 |
|---|---|
| 0–1 | CPU 全体の負荷（idle 以外）。太い棒 |
| 2 | 空き（区切り） |
| 3–7 | LED / Light / Heavy / Shell / Display の CPU 使用率 |

`07_led_matrix` との違い:

- **上半分**: 12 列 × 4 段の負荷の履歴をやめて、全体の負荷を 1 本の横棒にした。
  `07_led_matrix` の履歴はリングバッファを並べ直さずに描いていたので、
  「左が古く右が新しい」にはなっていなかった
- **下半分**: 「その瞬間に走っていたタスク」の記録をやめて、タスクごとの CPU
  使用率の横棒にした。記録するのが表示タスク自身なので、`07_led_matrix` では
  履歴がほとんど光らなかった
- **Light**: 自分の CPU 時間を 20 ms 使っては 60 ms 眠るようにした。Heavy 以外にも
  CPU を使うタスクがあると、行ごとの棒を足すと CPU 全体の棒になるのが見える
- **`top` コマンド**: マトリクスと同じ数字を 0.5 秒ごとに端末へ描き直す。
  もう一度 `top` で止まる。表示中も `kill 3` などを打てる

## 書き込む

```
pio run -d 07_led_matrix_v2 -t upload
pio device monitor -d 07_led_matrix_v2 -b 115200
```

シリアルを開くまで起動しない（`setup()` の `while (!Serial)`）のは他の章と同じ。

## 試す

```
> top
CPU [########    ] 60%

ID  NAME      STATE     CPU%  MATRIX
0   idle      READY     40%
1   LED       BLOCKED    0%
2   Light     READY     16%  ##
3   Heavy     READY     40%  #####
4   Shell     RUNNING    4%  #
5   Display   BLOCKED    0%

> kill 3
```

| 操作 | CPU 全体 | 目に見えること |
|---|---|---|
| 起動直後 | 約 60% | Light と Heavy の行に棒 |
| `kill 3` | 約 24% | Heavy の棒が消え、全体の棒が縮む |
| `kill 2` | 約 4% | 残るのは `top` を描いている Shell だけ |
| `exec 2` / `exec 3` | 元に戻る | |

値は UNO R4 WiFi の実機で `top` を読んだもの。

- **Heavy は止まらずに回り続けても 40〜50% しか取れない。** このカーネルの
  スケジューラは idle も普通のタスクと同じ順番で回すので、idle と分け合う
- **`top` の表示中は Shell が数 % 使う。** 端末を描き直す手間がそのまま出る
